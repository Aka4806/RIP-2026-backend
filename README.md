# Симуляция выполнения SQL-запроса с разными типами индексов. Услуги - типы индексов (B-tree, Hash, Bitmap) и размеры таблиц, заявка - расчет времени выполнения запроса и объема использованной памяти для каждого типа индекса на тестовых данных указанного размера.

# Логика работы системы
Пользователь указывает параметры SQL-запроса и выбирает несколько конфигураций индексов для сравнения. Система выполняет симуляцию запроса для каждой выбранной конфигурации и рассчитывает примерное время выполнения запроса и объём использованной памяти. Модератор управляет списком доступных конфигураций индексов и подтверждает заявки на симуляцию.

Производительность SQL-запроса зависит от типа индекса, размера тестовой таблицы, типа индексируемого поля и селективности данных. Поэтому характеристики индекса и тестовой таблицы необходимо хранить в таблице услуг, а параметры выполняемого запроса — в заявке. В связующей таблице между заявкой и конфигурацией индекса хранятся результаты симуляции: время выполнения запроса, объём использованной памяти и комментарий пользователя или модератора.

# Логика расчёта

Для каждой выбранной конфигурации индекса система выполняет симуляцию SQL-запроса и определяет:

execution_time_ms — время выполнения запроса;
memory_usage_mb — объём памяти, использованный при выполнении запроса.

На результат влияют:

index_type — тип используемого индекса;
table_size — количество строк в тестовой таблице;
key_type — тип индексируемых данных;
selectivity — селективность данных;
query_type — характер выполняемого SQL-запроса;
iterations_count — количество тестовых запусков.
