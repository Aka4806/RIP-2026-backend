# SQL Index API

REST API конфигураций индексов B-tree, Hash и Bitmap для SPA. Данные хранятся в PostgreSQL, изображения и видео — в MinIO. HTML-шаблонов и страниц в этом проекте нет.

## Запуск

Для этого проекта создана отдельная БД `rip_lab3` — копия данных ЛР2. БД `rip_lab2` не используется по умолчанию.

В PowerShell задайте параметры текущего сеанса:

```powershell
$env:PGPASSWORD="пароль PostgreSQL"
$env:PGDATABASE="rip_lab3"
$env:MINIO_ENDPOINT="localhost:9000"
$env:MINIO_BUCKET="media"
$env:MINIO_ACCESS_KEY="ваш access key"
$env:MINIO_SECRET_KEY="ваш secret key"
go run ./cmd/awesomeProject
```

API доступен по адресу `http://127.0.0.1:18083`. Проверять через Postman или Insomnia.
Бакет `media` должен существовать; ключи должны разрешать чтение, запись и удаление объектов. Для URL медиа требуется доступ на чтение объектов из клиента. Сервер не меняет политику доступа к бакету.

Необязательные переменные: `PGHOST` (localhost), `PGPORT` (5432), `PGUSER` (postgres), `PGSSLMODE` (disable), `APP_ADDR` (127.0.0.1:18083), `MINIO_SECURE` (false), `MINIO_PUBLIC_URL` (http://localhost:9000/media).
Секреты не записываются в исходный код. Файл `.env` не загружается приложением автоматически.

Для новой пустой БД схема находится в `database/schema.sql`; её не нужно выполнять повторно на уже созданной `rip_lab3`. Перед запуском сервиса в ней должен существовать пользователь с ID 2. На текущем компьютере пользователи и данные уже скопированы из ЛР2.

## Текущий пользователь

`internal/app/session/current.go`: константа `CurrentUserID = 2`, пользователь `petr`. Функция `CurrentUser()` возвращает единственный экземпляр значения через `sync.OnceValue`. Обработчики используют её при создании, публикации, удалении, чтении черновика и работе с лайками, сериализаторы — для `is_owner` и `is_liked`. Регистрация не меняет текущего пользователя. Авторизация будет реализована в следующей работе.

## HTTP методы

| Метод | URL | Входные данные | Успешный ответ |
|---|---|---|---|
| GET | `/api/indexes?table_size=1000000` | Необязательный точный фильтр размера таблицы | 200, массив опубликованных карточек |
| GET | `/api/feed/` или `/api/feed/6?next=true` | Необязательный ID и `next=true/false` | 200, одна опубликованная карточка |
| GET | `/api/indexes/draft` | ID не передаётся | 200, черновик текущего пользователя или пустой объект установленной структуры |
| POST | `/api/indexes` | `multipart/form-data`: `name`, файл `image`, файл `video` | 201, созданный черновик |
| PUT | `/api/indexes/{id}/publication` | JSON: `short_description`, `table_size`, `selectivity` | 200, опубликованная карточка |
| DELETE | `/api/indexes/{id}` | Без тела | 200, пустое тело |
| POST | `/api/indexes/{id}/likes` | JSON: `like` — 0 или 1 | 200, карточка с обновлёнными лайками |
| POST | `/api/users` | JSON: `username`, `password` | 201, ID и имя пользователя |
| POST | `/api/users/authentication` | Заглушка | 501, пустое тело |
| POST | `/api/users/authorization` | Заглушка | 501, пустое тело |

Всего 10 методов. Два варианта URL ленты обслуживаются одним обработчиком и одним маршрутом с необязательным ID. Для варианта без ID используйте завершающий `/`.

Коды ошибок: 400 — неверные данные, 404 — запись отсутствует, удалена, принадлежит другому пользователю или недоступна для перехода статуса; 409 — черновик уже существует или логин занят; 415 — неверный Content-Type; 500 — ошибка БД или хранилища. Заглушки возвращают 501, поскольку соответствующая функциональность ещё не реализована. Тело ошибок пустое, коды не дублируются в JSON.

## Формат карточки

```json
{
  "id": 6,
  "name": "B-tree 10M",
  "short_description": "B-tree для точного поиска и выборки диапазонов.",
  "image_url": "http://localhost:9000/media/btree_10m.png",
  "video_url": "http://localhost:9000/media/btree%2010M.MOV",
  "table_size": 10000000,
  "selectivity": 0.001,
  "likes_count": 3,
  "is_owner": 0,
  "is_liked": 0
}
```

Все 10 полей всегда присутствуют в ответах карточки. Пустые строки передаются как `""`, числовые значения пустого черновика — как 0. Для отсутствующего черновика `id=0`, `is_owner=0`; GET не создаёт запись. Пустой список — `[]`. Статус, пароль, идентификатор создателя и даты в JSON карточки не передаются.

`internal/app/serializer/index.go` содержит выходные структуры и преобразование модели. `image_url` и `video_url` в ответе — готовые URL, построенные из имён объектов в БД. `likes_count` вычисляется по связанной коллекции лайков, `is_liked` и `is_owner` — числа 0/1.

### Создание

В Postman выберите Body → form-data: `name` типа Text, `image` и `video` типа File. Не задавайте Content-Type вручную: клиент сформирует multipart boundary.

Оба файла обязательны. Изображения: PNG, JPEG, GIF, WebP до 10 МиБ. Видео: MP4, MOV, WebM до 50 МиБ. Сервер проверяет сигнатуру типа, а не только расширение; проверка длительности или перекодирование не выполняются. В `media/` есть небольшие примеры файлов для демонстрации.

Файлы получают имена `lab3_<случайное hexadecimal имя>.<расширение>`. В БД сохраняется только имя, например `lab3_c63f...a1.png`. Присланные URL и дополнительные поля не принимаются. Если загрузка или сохранение не удались, сервер пытается удалить уже загруженные объекты. Существующие файлы ЛР2 не изменяются.

### Публикация

```json
{
  "short_description": "B-tree хранит ключи в отсортированном виде и поддерживает поиск по равенству и диапазонам.",
  "table_size": 1000000,
  "selectivity": 0.01
}
```

Название задаётся при создании. Публикация заполняет описание и оба поля по теме. Описание — 1–500 символов, размер таблицы — целое число 1–2147483647, селективность — число от 0 до 1 включительно. Дополнительные JSON-поля запрещены; числовые поля обязательны.

### Статусы и права

Создание устанавливает `draft`, ID создателя и дату создания на сервере. Публикация разрешает только переход `draft → published` для своего черновика и устанавливает дату формирования. Удаление разрешает `draft/published → deleted` только для своих карточек. Возврата в черновик нет. Строки и связанные лайки при удалении карточки физически сохраняются, объекты MinIO также сохраняются.

Список и лента показывают только `published`. Запрос ленты по ID удалённой карточки, в том числе с `next=true`, возвращает 404. Следующая карточка выбирается по возрастанию ID с переходом к первой в конце списка.

### Лайки

```json
{"like": 1}
```

Значение 1 добавляет лайк текущего пользователя, 0 удаляет его строку из таблицы лайков. Повторное выполнение не создаёт дубликат и не приводит к ошибке. Черновики и удалённые карточки лайкать нельзя. Блокировка строки карточки согласует операции лайка и удаления.

### Пользователи

```json
{"username": "new_user", "password": "demo-password"}
```

Ответ регистрации содержит только `id` и `username`. Имя — 1–100 символов, пароль — 1–72 байта. Поле `users.password` содержит bcrypt-хеш, а не исходный пароль. `UNIQUE(password)` проверяет уникальность хешей, но не запрещает одинаковые исходные пароли из-за случайной соли. Данные входа исходных учебных пользователей сохранены при копировании БД.

## Таблицы PostgreSQL

### users

| Поле | Тип | Ограничения и назначение |
|---|---|---|
| id | integer identity | PK, NOT NULL, генерируется БД |
| username | varchar(100) | NOT NULL, UNIQUE, имя пользователя |
| password | varchar(255) | NOT NULL, UNIQUE, непустой bcrypt-хеш |

### index_configurations

| Поле | Тип | Ограничения и назначение |
|---|---|---|
| id | integer identity | PK, NOT NULL |
| name | varchar(150) | NOT NULL, название |
| short_description | varchar(500) | NULL допустим до публикации |
| status | varchar(20) | NOT NULL, CHECK draft/published/deleted |
| image_url | varchar(500) | NULL допустим; имя объекта изображения MinIO |
| video_url | varchar(500) | NULL допустим; имя объекта видео MinIO |
| table_size | integer | NOT NULL; 0 у нового черновика |
| selectivity | numeric(10,6) | NOT NULL; 0 у нового черновика |
| created_at | timestamp | NOT NULL, дата создания |
| creator_id | integer | NOT NULL, FK → users.id, ON DELETE RESTRICT |
| formed_at | timestamp | NULL до публикации |

Индекс `uq_one_draft_per_user` уникален по `creator_id` только для `status='draft'`. Проверка в транзакции с блокировкой пользователя предотвращает одновременное создание двух черновиков. Модератор и дата завершения не добавлены: они не используются бизнес-логикой конфигураций индексов в этих лабораторных.

### index_configuration_likes

| Поле | Тип | Ограничения и назначение |
|---|---|---|
| id | integer identity | PK, NOT NULL |
| user_id | integer | NOT NULL, FK → users.id, ON DELETE RESTRICT |
| index_configuration_id | integer | NOT NULL, FK → index_configurations.id, ON DELETE RESTRICT |

Пара `(user_id, index_configuration_id)` уникальна. Это связь многие-ко-многим пользователей и конфигураций. Каскадного удаления нет. Все операции API с данными выполняются через GORM.

## Проверка через Postman

Импортируйте `postman/SQL-Index-LR3.postman_collection.json`. Коллекция содержит ровно 10 запросов, переменная `base_url` уже настроена. В запросе создания выберите локальные `media/btree_100k.png` и `media/btree_100k.mp4`. Путь может потребовать повторного выбора после импорта.

Последовательно выполните список с фильтром, создание, получение черновика и публикацию. При создании Postman сохраняет `index_id`. Если есть старый черновик, GET черновика покажет его; удалите его запросом DELETE по этому ID либо опубликуйте, затем повторите создание.

Запрос ленты сначала выполните с пустым `feed_id` и `next=false`. Затем в переменных коллекции установите `feed_id` равным ID опубликованной карточки и `next=true` и выполните тот же запрос повторно. Сравните ID ответа. Для демонстрации отмены лайка повторите запрос лайка с `{"like":0}`. Далее удалите созданную карточку, проверьте её URL и зарегистрируйте пользователя. Последние два запроса показывают заглушки 501.

Для проверки данных в Adminer выберите именно `rip_lab3`:

```sql
SELECT id, name, status, image_url, video_url, table_size, selectivity,
       creator_id, created_at, formed_at
FROM index_configurations ORDER BY id;

SELECT id, user_id, index_configuration_id
FROM index_configuration_likes ORDER BY id;

SELECT id, username, password FROM users ORDER BY id;
```

## Тесты

```powershell
go test ./...
$env:TEST_DATABASE="1"
$env:PGDATABASE="rip_lab3"
$env:PGPASSWORD="пароль PostgreSQL"
go test ./...
```

Интеграционный тест использует транзакцию с откатом, включая тестовых пользователей, карточки и лайки. Последовательности ID могут увеличиться — это штатное поведение PostgreSQL. Не запускайте интеграционный тест на рабочей БД с параллельными пользователями: на время теста он блокирует изменяемые строки.

Для проверки настоящей загрузки дополнительно задайте ключи MinIO и `$env:TEST_MINIO="1"`. Тест проверит доступность загруженных файлов по HTTP и удалит свои объекты после проверки. Без этого флага MinIO подменяется тестовым хранилищем; проверяется и очистка файлов при неудачной загрузке.

## Структура проекта

- `cmd/awesomeProject` — запуск сервера.
- `internal/api` — маршруты и интеграционные тесты.
- `internal/app/handler` — HTTP-обработчики и проверка входных данных.
- `internal/app/repository` — операции GORM и транзакции.
- `internal/app/models` — модели таблиц и хеширование паролей.
- `internal/app/serializer` — постоянная структура JSON-ответов.
- `internal/app/session` — singleton текущего пользователя.
- `internal/app/storage` — загрузка и удаление объектов MinIO.
- `internal/database` — подключение к PostgreSQL.
- `database/schema.sql` — схема для новой пустой БД.
- `postman` — коллекция запросов.
- `media` — примеры файлов для загрузки.
